「AI実行の記録100%」は、すべてのAgent実行を監査ログ（ExecutionLog）へ記録する設計を指します。効果を示す実測の改善率ではなく、システムの仕様です。

基本思想

AIが作る。人が判断する。システムが記録する。

AI → 下書き → 承認 → 実行 → 監査ログ。これを全業務で繰り返します。

だから、単なる「AI自動化ツール」ではありません。AIを組み込んだ業務オペレーション基盤——それがAI工場OSです。

記事を書く、SEOを改善する、自社製品を開発する、iOSアプリを作る、案件を管理する、収益を分析する——業務の中身は違っても、進み方は同じです。AIが下書きをつくり、人が確認し、承認されたものだけが実行される。

この共通の形を1つの基盤にまとめ、業務ごとに「工場」として並べたものがAI工場OSです。各工場の進行状況・収益・承認待ちは、AI工場モニタという1つの管制塔ダッシュボードから横断的に確認できます。

業務を「担当者ごとの属人的な作業」ではなく「AIと人が交互に手を入れる1本のライン」として捉える。

それが、AI工場OSという名前に込めた考え方です。

01コンテンツ・SEO工場

素材収集から執筆、事実確認、公開まで、ブログ記事の制作を自動で進めています。クライアント向け記事は構成案の承認から本文の仕上げまで自動で進み、修正も対話形式で、どこがどう変わったかを確認しながら行えます。公開後もアクセスデータを取得し、リライト提案・動画化まで一気通貫でつながります。

  1. 素材収集・事実抽出 — 記事の元になる情報を集め、事実関係を整理します
  2. 検索意図・競合調査 → 本文執筆 — Web検索を伴う調査をもとに、AIが本文を執筆します
  3. 事実確認・品質チェック — 集めた事実との整合性、品質基準をAIがチェックします
  4. 内部リンク設計 → 承認 → 公開 — 承認後、自社ブログ・クライアント先へ公開します
  5. 公開後もデータを取得 — アクセス状況を取得し、リライト提案・動画化連携まで継続します

02マーケティング・集客工場

「連絡への対応」と「発信・告知」の2種類を担当する工場です。Gmailを定期的に監視し、LPの問い合わせ・紹介・ランサーズ／クラウドワークス／Wantedly／LinkedInなどから届くメールを自動で検知。内容に応じて返信文・提案の骨子・料金の目安、または応募文の下書きをAIが作成します。あわせて、公開したブログ記事・Note・YouTube動画について、X・Threads・LinkedIn・Facebook・Instagramそれぞれの文体に合わせた告知文の下書きも作成します。実際の送信・投稿は人が行います。

  1. Gmailを定期的に監視 — 対象の送信元からの新着メールを検知します（読み取り専用）
  2. 内容に応じてAgentを振り分け — 問い合わせ・紹介は「提案・見積Agent」、クラウドソーシングの案件通知は「案件探し・応募Agent」が担当します

  5. 送信・投稿は人が行う — 下書きを確認し、実際の送信・応募・投稿は人が判断して行います

WORKFLOW

AIが下書きし、人が承認する

どの工場も、進み方は同じです。AIに任せきりにせず、かといって人がゼロから作るのでもない、下書きと承認の往復で進みます。

実行単位Agent・Task・Artifact・Workflow

各工場には、業務ごとの役割を持ったAgent（例：構成作成、本文執筆、市場調査）が登録されています。AgentはTaskを実行してArtifact（成果物）を生成し、複数のTaskをつないだものがWorkflowです。外部公開・外部送信・本番反映・重要データ変更を伴うステップには承認フラグが立ち、これを通らない限り完了扱いにはなりません。

  1. Taskを実行 — 手動実行、または夜間の無人実行（後述）でAgentがTaskを開始します
  2. AIが下書きを作成 — Agentが成果物（Artifact）を生成します。すべての実行はExecutionLogに記録されます
  3. 承認が必要なら止まる — 外部公開など重要な操作の手前でWorkflowはWAITING_APPROVAL状態になり、次には進みません
  4. 人が承認・却下 — 内容を確認し、承認すれば実行が再開、却下すれば差し戻されます
  5. 監査ログに記録 — 誰が・何を・いつ承認したかが記録され、あとから追跡できます

承認待ち画面（実際の画面。デモデータです）。「外部公開・外部送信・本番Deploy・決済・契約・重要データ変更は人間の承認なしに実行されません」という方針をそのまま画面にしています

無人実行コスト上限つきの夜間実行

承認不要な工程（市場調査や構成案づくりなど）は、夜間に無人で実行するワーカーに任せています。1回の起動で実行するTask数・Workflow数の上限、1日あたりのAI利用コスト上限、古くなった実行ロックの自動解放、二重起動の防止を設けたうえで、Windowsのタスクスケジューラから定期実行しています。暴走を防ぎながら、人の手が空いていない時間帯も業務を進められる仕組みです。

毎日02:00の定期実行では、収益化工場が売上の点検と報告を、分析・改善工場が運転データの分析を、PMO・プロジェクト管理工場が案件の進行確認と朝の報告を、それぞれ無人で進めます。夜の間に整理された内容を、朝にまとめて確認できます。

SECURITY & GOVERNANCE

何を承認したか、誰がアクセスできるかを、常に管理下に置く

権限管理
3段階のロール（ADMIN / OPERATOR / VIEWER）
閲覧のみ・実行と承認・全操作、の3段階で権限を分けます。判定ロジックは1箇所に集約し、UIでボタンを隠すだけの制御にはしていません。

承認ゲート
重要操作は1つの判定関数を必ず経由
外部公開・外部送信・本番反映・重要データ変更は、承認ポリシーを判定する1つの関数を経由しない限り完了扱いにできない構造にしています。
監査ログ
全AI実行を記録
Agentの実行はすべてExecutionLogに記録されます。ログを伴わないAI実行の経路は作らない設計です。
コスト管理
利用状況の可視化と上限
AI利用コストをAI工場モニタで可視化し、1日あたりの上限を超えそうな場合はアラートを出し新規実行を止めます。
秘密情報の扱い
ソースコード・DB・ログに書かない
APIキー等の秘密情報は専用のシークレット管理から読み込み、コード・データベース・ログには一切記録しません。

自社プロダクトのアイデアをナレッジとして登録・一覧管理しています。AI工場OS自体の機能追加は、私たちがClaude Codeを使って直接実装しており、自分たちが使うツールを自分たちで作り、使いながら直していくサイクルを実践しています。

運用基盤Windowsタスクスケジューラによる夜間無人実行

承認不要な工程を対象に、1日あたりのコスト・実行数の上限を設けたうえで夜間に自動実行しています。実行が失敗して残ったロックは一定時間で自動解放し、翌朝には結果をサマリーとして確認できます。

FAQ

よくあるご質問

AI工場OSは外部の会社にも提供してもらえますか？
現時点ではパッケージ製品としての外部提供は行っていません。ただし、同じ考え方（AIが下書きし人が承認する、全実行をログに残す）で貴社専用の仕組みを構築するご相談は承っています。まずは無料相談からお気軽にお問い合わせください。
AIにどこまで任せているのですか？
AIが担当するのは「下書きを作る」工程までです。外部への公開・送信、本番環境への反映、重要データの変更を伴う操作は、必ず人間の承認を経てから実行されます。承認を経ずに完了扱いにできない構造にしているため、AI任せで気づかないうちに何かが公開される、という状態は起きません。
実行内容はあとから確認できますか？
はい。すべてのAI実行を監査ログ（ExecutionLog）に記録しており、いつ・どのAgentが・何を実行し・誰が承認したかを、あとから追跡できます。
どのAIを使っていますか？費用はどれくらいですか？
既定ではAnthropic社のClaude CLI（サブスクリプション契約）を使っており、従量課金のAPIキーを必要としません。AI工場モニタに表示されるコストは、同じ処理をAPI課金で行った場合の参考値であり、実際の請求額そのものではありません。
iOSアプリはどのように使えますか？
AI工場モニタと同じ情報（総売上・稼働工場数・承認待ち・アラートなど）を、外出先からiOSアプリで確認できます。Bearer Token方式で認証したうえで既存のAPIに接続する仕組みです。
